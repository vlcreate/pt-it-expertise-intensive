# Фид индикаторов компрометации

Программный комплекс `main.py` предназначен для генерации фида индикаторов компрометации (IoC) в формате JSONL на основе 100 актуальных образцов вредоносного ПО из MalwareBazaar. Данные обогащаются результатами антивирусного сканирования VirusTotal и аналитикой из базы APT ETDA.

Архитектура скрипта включает четыре логических модуля: импорт данных, корреляция, аналитическая обработка и экспорт.

## Развертывание и запуск

Зависимости сторонних библиотек отсутствуют (требуется стандартная библиотека Python версии 3.10 и выше). 

Конфигурация среды:
```bash
cp secrets.env.example secrets.env   # Внести ключи аутентификации VT_API_KEY и MB_AUTH_KEY
python main.py
```

Итоговый фид формируется в файле `output/malware_feed.jsonl` (одна запись на строку):
```json
{"md5": "c794a375acde0bd7d8668ba587b49587", "sha256": "fba02b35c4c5...", "malware_class": ["Trojan", "Trojan-Dropper"], "malware_family": ["Mirai"], "av_detects": ["Linux.Trojan.Gafgyt", "..."], "threat_level": "MEDIUM"}
```

Первичное выполнение скрипта занимает около 30 минут ввиду ограничений бесплатного тарифа API VirusTotal (4 запроса в минуту для 100 образцов). Ответы API сохраняются в директории локального кэша `data/raw`, что обеспечивает выполнение повторных запусков за несколько секунд без дополнительных сетевых запросов.

## Конфигурация аутентификации

Параметры доступа задаются в конфигурационном файле `secrets.env`:
```env
VT_API_KEY=...        # Ключ API профиля VirusTotal
MB_AUTH_KEY=...       # Ключ аутентификации auth.abuse.ch (предоставляет доступ к MalwareBazaar)
HTTPS_PROXY=...       # Опциональный параметр
```

Использование HTTP-прокси (`HTTPS_PROXY`) рекомендовано в случае блокировки прямого доступа к API `virustotal.com` (например, при разрыве соединения на этапе TLS-handshake, сопровождающемся ошибкой `WinError 10054`, при исходящих запросах с российских IP-адресов). Доступ к сервисам MalwareBazaar и ETDA осуществляется без проксирования.

## Алгоритм классификации ВПО (malware_class)

Определение класса вредоносного ПО выполняется по каскадной модели с использованием трех источников (до первого успешного совпадения):

1. **База APT ETDA**: идентификация семейства с последующей трансляцией внутреннего типа ETDA в целевой класс из справочника (`TYPE_TO_CLASS`).
2. **Суффикс наименования**: при отсутствии данных в ETDA анализируется суффикс названия (например, `RustyStealer` классифицируется как Trojan-PSW, `PureRAT` — как Backdoor, согласно маппингу `SUFFIX_TO_CLASS`).
3. **Категоризация VirusTotal**: резервный метод на основе категорий отчета платформы (`trojan`, `ransomware`, `stealer` и др.).

Статистика применения алгоритма на тестовой выборке: база ETDA — 7 записей, суффикс наименования — 43 записи, категоризация VirusTotal — 48 записей. Для 2 образцов класс идентифицировать не удалось.

## Оценка уровня угрозы (threat_level)

Классы ВПО из исходного справочника распределены по трем категориям риска на основе их деструктивного потенциала:
* **HIGH**: получение контроля над скомпрометированной системой, шифрование данных, кража учетных данных и финансовых средств.
* **MEDIUM**: векторы доставки нагрузки, средства распространения, создание сетевых аномалий, инструментарий атакующего.
* **LOW**: потенциально нежелательное ПО (прямо не классифицируемое как вредоносное), рекламные и спам-модули.

Итоговый уровень угрозы присваивается по наивысшей категории среди всех идентифицированных классов образца. Дополнительно применяется повышающий коэффициент: наличие подтвержденной связи семейства с APT-группировкой (на основании данных ETDA) автоматически повышает уровень угрозы на одну ступень.


## Ограничения реализации

* **Отсутствие сигнатур в MalwareBazaar**: поле `signature` заполнено не для всех образцов (в тестовой выборке — 61 из 100). Для объектов без сигнатуры класс определяется исключительно на основе отчета VirusTotal, что снижает гранулярность классификации.
* **Специфика базы ETDA**: реестр ориентирован на инструментарий целевых атак и не репрезентативен для массового потока ВПО (в тестовой выборке в ETDA было идентифицировано только 5 из 40 уникальных семейств).
* **Субъективность оценки риска**: распределение классов ВПО по трем группам угрозы основано на авторской категоризации. Спорные или пограничные случаи классификации задокументированы в соответствующем разделе расширенного отчета.
